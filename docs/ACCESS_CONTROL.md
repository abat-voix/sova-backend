# Ролевая модель СОВА

Источником прав служит `accounts.policy`. Клиент получает готовый список
операций из `/api/auth/me/`; окончательное решение всегда принимает API.
Django superuser получает все операции независимо от прикладной роли.
Активный пользователь без прикладной роли не получает доступа к бизнес API.

## Матрица разделов

| Раздел | Наблюдатель | КАМ | Руководитель | Администратор платформы |
| --- | --- | --- | --- | --- |
| Взаимодействия | Все, чтение | Свои и неназначенные, работа | Команда, работа | Все, работа |
| Договоры | Все, чтение и скачивание | Свои и неназначенные, работа | Команда, работа | Все, работа |
| Лицензии | Все, чтение | В пределах своих договоров, работа | В пределах договоров команды, работа | Все, работа |
| Задачи и процессы | Все, чтение | В пределах своих взаимодействий, выполнение | В пределах взаимодействий команды, выполнение | Все, выполнение |
| Отчёты | Просмотр и экспорт | Просмотр и экспорт | Просмотр и экспорт | Просмотр и экспорт |
| Справочники | Чтение | Работа с записями | Работа с записями | Работа с записями, импорт и маппинги |
| Workflow | Нет | Нет | Свои шаблоны | Все шаблоны |
| Пользователи | Нет | Нет | Просмотр для команды | Полное управление |
| Команды | Нет | Нет | Своя команда | Все команды |
| Интеграции | Нет | Нет | Нет | Управление |
| Уведомления, сообщения, realtime | Нет | Личные | Личные | Личные |

## Привязка API к операциям

| API | Операции политики |
| --- | --- |
| `interactions` и состав взаимодействия | `interactions.*` |
| `contracts`, `contract-files` | `contracts.*` |
| `licenses` | `licenses.*` |
| `workflow-instances`, `stage-instances`, `action-instances`, результаты, откаты и вложения | `processes.*` |
| `reports` | `reports.read`, `reports.export` |
| CRUD справочников | `catalog.read/create/update/delete` |
| Импорт и маппинги импорта | `catalog.import`, `catalog.mappings.manage` |
| Администрирование workflow | `workflows.manage` |
| Пользователи и команды | `users.read/manage`, `teams.manage` |
| Интеграции | `integrations.manage` |
| Уведомления, сообщения и websocket | `notifications.use`, `messaging.use`, `realtime.connect` |

Для ViewSet операция задаётся в `policy_actions` по имени DRF action. Для
APIView используется `policy_action`. Если действие ViewSet не перечислено,
запрос запрещается. Область видимости записей задаётся через
`READ_SCOPES` и предметные функции в `VISIBILITY_RULES`.
