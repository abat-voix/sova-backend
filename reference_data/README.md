# Справочные данные

В этой папке хранятся исходные справочники для наполнения системы. Загружаются командой
`./manage.py loaddata <файл>.xlsx` (запускать из корня проекта — команда ищет файл по указанному пути,
а если он не абсолютный, то дополнительно и в этой папке).

Все справочники разом загружает флаг `./manage.py loaddata --reference-data`: он берёт из этой папки все
файлы из таблицы ниже и грузит их в порядке зависимостей (вузы → вендоры → направления → программы →
продукты), поэтому связи `programs.direction`, `products.vendor` и `products.programs` резолвятся в том же
прогоне. Флаг не принимает имена файлов и работает в одной транзакции: если хотя бы одного файла нет или в
каком-то из них ошибка, не загружается ничего.

| Файл | Справочник | Обязательные колонки |
|---|---|---|
| `universities.xlsx` | Вузы (`University`) | `id`, `ror`, `name_en`, `name`, `short_name`, `country_code`, `type`, `works_count`, `cited_by_count`, `city`, `region`, `lat`, `lon`, `homepage_url` |
| `vendors.xlsx` | Вендоры (`Vendor`) | `name`, `external_code` |
| `directions.xlsx` | Направления (`Direction`) | `name`, `external_code` |
| `programs.xlsx` | Программы (`Program`) | `name`, `direction` (название или `external_code` направления — должно уже быть загружено) |
| `products.xlsx` | Продукты (`Product`) | `name`, `external_code`, `vendor` (название или `external_code` вендора — должен уже быть загружен) |
| | | необязательная колонка `programs` — список программ через `;` (по названию), связывает M2M `Product.programs`; отсутствие колонки существующие связи не трогает, а пустая колонка их очищает |

Правила:

- один справочник — один файл;
- первая строка содержит названия колонок; лишние колонки игнорируются, порядок не важен;
- необязательная колонка `is_active` (да/нет, true/false, 1/0) есть у всех справочников, кроме `universities.xlsx`;
  по умолчанию `true`;
- апсерт идёт по `external_code`, если он заполнен, иначе по естественному ключу (обычно `name`; для `products.xlsx` —
  пара `name`+`vendor`; у `Program` нет поля `external_code`, поэтому `programs.xlsx` апсертится всегда по паре
  `name`+`direction`);
- персональные данные, пароли и другие секреты сюда не добавляются;
- историю изменений файлов хранит Git, поэтому даты и версии в имени файла не нужны.

`universities.xlsx` содержит 834 строки выгрузки вузов.

`vendors.xlsx`, `directions.xlsx`, `products.xlsx`, `programs.xlsx` заполнены данными, собранными с каталога курсов
edu-rt.ru/course:

- `directions.xlsx` — 5 направлений из фильтра категорий сайта, `external_code` — id категории на сайте
  (`setCategory('N')`), пригодится, если справочник понадобится переподгрузить;
- `programs.xlsx` — 12 курсов сайта как программы, каждая привязана к своему направлению;
- `products.xlsx` — 17 инструментов/технологий, явно упомянутых в программе курсов (темы модулей), а не из общего
  маркетингового описания — там на всех страницах шаблонно повторяются нерелевантные упоминания;
- `vendors.xlsx` — один вендор, `ПАО «Ростелеком»`, единственный явно названный на сайте (для продукта
  «Система «Яга»»); у остальных продуктов вендор пуст — сайт его не указывает, и на основе общих знаний он не
  проставлялся, чтобы не вносить в справочник непроверенные предположения.

Два курса («Графический дизайн интерфейсов», «Введение в информационную безопасность») не дали ни одного продукта —
в их программе нет конкретных инструментов, только темы/категории. Продукты связаны с программами через колонку
`programs` в `products.xlsx` (M2M `Product.programs`).
